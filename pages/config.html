Reference ​

Global ​

PropertyDefaultDescription
scrape_timeout10sScrape timeouts ensure that scraping completes in reasonable time, and slow queries are canceled early when the database is already under heavy load
scrape_timeout_offset500msOffset subtracted from Prometheus scrape_timeout to give us some headroom and prevent Prometheus from timing out first. Must be strictly positive.
scrape_error_drop_interval0sInterval between dropping scrape_errors_total metric. By default metrics are persistent.
min_interval0sMinimum interval between collector runs. By default collectors are executed on every scrape. Essentially this is a cache TTL for collector results, but it also applies to the first scrape after startup, so it can be used to stagger expensive collector runs and avoid overloading the database.
warmup_delay0sDelay between collector scrapes during the startup cache warmup. This can be used to avoid overloading the database with expensive queries (thundering herd) when the cache is empty and all collectors are executed at once. It's intended to be used together with 'min_interval' to stagger collector runs. By default all collectors are executed immediately on the first scrape.
max_connections3Maximum number of open connections to any one target. Metric queries will run concurrently on multiple connections, as will concurrent scrapes.
max_idle_connections3Maximum number of idle connections to any one target. Unless you use very long collection intervals, this should always be the same as max_connections.
max_connection_lifetime0sMaximum amount of time a connection may be reused to any one target

Timeouts ​

Prometheus informs targets of its own scrape timeout (via the X-Prometheus-Scrape-Timeout-Seconds request header) so the actual timeout is computed as:

text
min(scrape_timeout, X-Prometheus-Scrape-Timeout-Seconds - scrape_timeout_offset)

If scrape_timeout ≤ 0, no timeout is set unless Prometheus provides one.

Target (Single target mode) ​

The target to monitor and the collectors to execute on it.

PropertyTypeDescription
nameString?(Optional) Target name. Setting this field enables extra metrics e.g. up and scrape_duration with the target label that are always returned on a scrape.
data_source_nameStringData source name always has a URI schema that matches the driver name. In some cases (e.g. MySQL) the schema gets dropped or replaced to match the driver expected DSN format.
collectorsList(String)Collectors (referenced by name) to execute on the target.
enable_pingBooleanIn case you need to connect to a backend that only responds to a limited set of commands (e.g. pgbouncer) or a data warehouse you don't want to keep online all the time (due to the extra cost), you might want to disable ping
Click to expand - Single target mode example
yaml
target:
  name: "prices_db"
  data_source_name: "sqlserver://prom_user:prom_password@dbserver1.example.com:1433"
  collectors: [pricing_data_freshness, pricing_*]
  enable_ping: true

Collectors ​

A collector is a named set of related metrics that are collected together. It can be referenced by name, possibly along with other collectors.

Collectors may be defined in two inclusive ways:

  1. inline in the exporter configuration file, under the collectors field;
  2. as separate files (one collector per file), and referenced in the collector_files of the exporter configuration file, making them easy to share and reuse.
PropertyTypeDescription
collector_nameString?(Optional) Target name. Setting this field enables extra metrics e.g. up and scrape_duration with the target label that are always returned on a scrape.
min_intervalStringSimilar to global.min_interval, but applies to this collector only.
metricsList(MetricSpec)List of Metric definitions
queriesList(QuerySpec)?(Optional) List of Query definitions

Metric ​

A metric is a Prometheus metric with name, type, help text and (optional) additional labels, paired with exactly one query to populate the metric labels and values from.

PropertyTypeDescription
metric_nameStringThe metric name, type and help text, as exported to /metrics
type(counter|gauge)Underlying metric type so Prometheus and monitoring tools know how to interpret and query the data
helpStringHuman-readable description or documentation string for a metric
queryStringSQL query to execute.
key_labelsSet(String)?Set of labels derived from the existing result set columns
valuesList(String)Column name(s) to return as a metric value. Can be multiple but requires value_label
value_labelString?Label populated with the value column name, configured via values. Required when multiple value columns are configured
static_labelsMap(String)?Arbitrary key/value pairs
static_valueIntegerArbitraty static value. Useful, when not the value matters, but the string data (populated as labels)
timestamp_valueString?Timestamp column name to return a metric with an explicit timestamp
no_prepared_statementBooleanDo not use a prepared statement if true. Might be required to execute queries against some backends (e.g. Clickhouse, PGBouncer)
query_refString?Query name (referenced by name)

The result columns conceptually fall into two categories:

  • zero or more key_labels columns: their values will be directly mapped to labels of the same name;
  • one or more values columns:
    • if exactly one value column, the column name is ignored and its value becomes the metric value;
    • with multiple value columns, a value_label must be defined; the column name will populate this label and the column value will populate the metric value.

Queries ​

Named queries, referenced by one or more metrics, through query_ref.

PropertyTypeDescription
query_nameStringThe query name to be used as a reference
queryStringSQL query to execute.
no_prepared_statementBooleanDo not use a prepared statement if true. Might be required to execute queries against some backends (e.g. Clickhouse, PGBouncer)
Click to expand - Collector example
yaml
collector_name: pricing_data_freshness

metrics:
  - metric_name: pricing_update_time
    type: gauge
    help: "Time when prices for a market were last updated."
    key_labels:
      - Market
    static_labels:
      portfolio: income
    values: [LastUpdateTime]
    query: |
      SELECT Market, max(UpdateTime) AS LastUpdateTime
      FROM MarketPrices
      GROUP BY Market

Collector Files ​

NOTE

The collectors and collector_files configurations also support Glob pattern matching. To match names with literal pattern terms in them, e.g. collector_*1*, these must be escaped: collector_\*1\*.

PropertyTypeDescription
collector_filesList(String)Collector files specifies a list of globs. One collector definition per file.

Complete Example ​

Click to expand ./sql_exporter.yml:
yaml
global:
  scrape_timeout: 10s
  scrape_timeout_offset: 500ms
  scrape_error_drop_interval: 0s
  min_interval: 0s
  warmup_delay: 0s
  max_connections: 3
  max_idle_connections: 3

target:
  name: mssql_database
  data_source_name: "sqlserver://prom_user:prom_password@dbserver1.example.com:1433/dbname"
  collectors: [mssql_standard]
  enable_ping: true

collectors:
  - collector_name: mssql_standard
    metrics:
      # The metric name, type and help text, as exported to /metrics.
      - metric_name: mssql_log_growths
        type: counter
        help: "Total number of times the transaction log has been expanded since last restart, per database."
        key_labels:
          - db
        static_labels:
          env: dev
          region: europe
        values: [counter]
        query: |
          SELECT rtrim(instance_name) AS db, cntr_value AS counter
          FROM sys.dm_os_performance_counters
          WHERE counter_name = 'Log Growths' AND instance_name <> '_Total'

      # A different metric, with multiple values produced from each result row.
      - metric_name: mssql_io_stall_seconds
        type: counter
        help: "Stall time in seconds per database and I/O operation."
        key_labels:
          - db
        value_label: operation
        values:
          - io_stall_read
          - io_stall_write
        query_ref: io_stall

      # Another metric, uses same named query (referenced through query_ref) as mssql_io_stall_seconds.
      - metric_name: mssql_io_stall_total_seconds
        type: counter
        help: "Total stall time in seconds per database."
        key_labels:
          - db
        values:
          - io_stall
        query_ref: io_stall

      # Metric with a static value to retrieve string data.
      - metric_name: mssql_hostname
        type: gauge
        help: "Database server hostname"
        key_labels:
          - hostname
        static_value: 1
        query: |
          SELECT @@SERVERNAME AS hostname

    # Named queries, referenced by one or more metrics, through query_ref.
    queries:
      - query_name: io_stall
        query: |
          SELECT
            cast(DB_Name(a.database_id) as varchar) AS db,
            sum(io_stall_read_ms) / 1000.0 AS io_stall_read,
            sum(io_stall_write_ms) / 1000.0 AS io_stall_write,
            sum(io_stall) / 1000.0 AS io_stall
          FROM
            sys.dm_io_virtual_file_stats(null, null) a
          INNER JOIN sys.master_files b ON a.database_id = b.database_id AND a.file_id = b.file_id
          GROUP BY a.database_id

collector_files:
  - "*.collector.yml"
